# RemoteFlow v0.5.0

发布日期：2026-09-05

上一正式版本为 v0.4.0。本版以「默认分组保护与规则」为主体，并包含 VNC 输入发送链路
崩溃修复与 VNC 会话三档缩放。

> **VNC 两项（输入修复 / 三档缩放）仅通过编译与自动化测试，本机实机验收在发布时
> 尚未完成**，如在使用中发现问题请在 v0.5.1 修复。

## Added（默认分组保护与规则）

- **数据模型显式三身份**：`connection_groups` 新增 `is_default` / `is_protected` 两列
  （DB schema v3），不再靠名称判断；重命名后仍保持默认身份。
- **首装默认分组「我的设备」**：默认展开、新建连接默认进入、默认受保护；「未分组」
  仍是系统兜底组（不可改名/删/移、空时隐藏）。
- **保护（锁定）规则**：受保护的默认分组不可重命名 / 删除 / 移动层级，但仍可增删
  连接、创建子分组、展开折叠。
- **设置 → 常规 → 分组**：新增「保护默认分组」开关（默认开），标题随默认组名变化；
  关闭后才允许重命名 / 删除 / 移动。
- **删除默认分组流程**：有其他普通分组时弹「选择新的默认分组」（取消即中止删除）；
  无其他普通组则回落「未分组」。
- **「设为默认分组」**：分组右键新增入口，避免无法再设默认；存在受保护默认组时禁用
  （防止借换默认绕过保护）。
- **删光不再复活**：首启种子经 `DefaultGroupResolver` 记标记；用户删光所有分组后重启
  不会自动重建默认组，新建连接回落「未分组」。

## Added / Changed（VNC）

- **输入发送崩溃修复（根因）**：VNC 输入消息入队时泛型被收窄成基接口，库按“任意
  首个”消息类型序列化，发送循环抛 `ArgumentException`（实机日志 `Message is no
  ClientCutTextMessage`）直接死亡，远端收不到鼠标/键盘。已改为携带具体消息类型
  描述符入队；发送失败从 Debug 升级为 Warning 不再静默。
- **会话三档缩放**：VNC 工具条缩放按钮改为三档循环：等比适应（留黑边）→ 拉伸铺满
  （填满变形）→ 1:1 原始（滚动条）；档位记忆到该连接，重开会话恢复。
- 临时 `[VNC INPUT]` 调试日志（验收后移除）。

## Fixed

- 默认分组受保护后右键菜单置灰与原生右键打开路径守卫不一致（统一挂
  `ContextMenu.Opened`）。
- 星期/周数开关持久化（v0.4.0 已修，本版连带纳入发布）；保护开关写库失败提示。
