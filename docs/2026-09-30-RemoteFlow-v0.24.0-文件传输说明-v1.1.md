# RemoteFlow 文件传输说明（开发中，拟随 v0.24.0）

> 状态：功能已在分支 `feature/file-transfer` 开发完成并通过自动化测试；**尚未在真实主机上验证，尚未发布**。

## 入口

| 场景 | 入口 | 通道 |
| --- | --- | --- |
| SSH 会话内 | 标题栏工具条 / 全屏药丸中的「文件传输」按钮，右侧停靠侧栏 | SFTP（会话认证信息另开一条独立连接，不占用终端通道） |
| 不连接会话（SSH） | 连接工作台 / 首页行右键、详情面板「⋯」→「文件传输…」 | SFTP |
| 不连接会话（RDP） | 同上 | 按连接选择：SMB 管理共享（默认）或 SFTP |
| VNC | 入口置灰 | 不支持 |

RDP 连接的通道与 SFTP 端口在「编辑连接 → 文件传输」中设置，保存在连接的 `options_json`，无需数据库迁移。

## 能力

浏览、上传 / 下载文件与文件夹、传输队列（进度 / 取消 / 清除已完成）、新建文件夹、重命名、删除、覆盖确认（覆盖 / 跳过 / 重命名 / 全部应用 / 取消）、复制路径。不含拖拽与断点续传。

## 安全设计

- 下载先写 `.rfpart` 临时文件再原子改名；取消 / 失败清理临时文件，最终路径不留半截文件。
- 远端文件名做净化并校验落盘路径仍在目标目录之内（拒绝 `..`、分隔符、盘符、`:`、保留名）。
- 不跟随符号链接 / junction 递归；深度上限 64、条目上限 20 万；并发 2 个传输。
- 凭据只在打开通道时解析，打开后立即释放；日志不记录文件内容。
- SMB 不强行断开用户已有连接（错误 1219 时提示先断开）。

## 限制与已知问题

- 仅 Windows 版提供；macOS 版未做（本机无法编译验证）。
- SMB：仅 445 端口，需管理共享未被禁用且账号有权限，通常仅适用于局域网 / VPN。
- SFTP 需要目标运行 OpenSSH Server；Windows OpenSSH 的用户名格式（`域\用户` / `用户@域`）未验证。
- 不支持 keyboard-interactive / 多因素认证（与现有 SSH 一致）。
- 未经真机验证：SSH 会话内 SFTP、`SshSession` 重构后终端连接、SMB（含 1219）、200MB 传输期间终端响应。
- Mac 端编辑连接后保存是否保留新字段未验证；旧版本客户端经云同步覆盖连接时会重置该字段。
