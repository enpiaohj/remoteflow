# RemoteFlow v0.24.0 文件传输说明

> 文档版本 v1.1（2026-09-30）｜适用版本：RemoteFlow Windows v0.24.0｜macOS 版本未含文件传输

v0.24.0 新增**文件传输**：在 SSH 会话里直接开右侧文件侧栏，或者**不建立任何会话**，对某台主机单独打开一个文件传输 Tab。
SSH 主机走 SFTP；RDP 主机因为协议本身没有文件传输通道，改走 **SMB 管理共享**或 **SFTP**，按连接选择。

---

## 1. 两个入口

| 场景 | 入口 | 通道 | 说明 |
| --- | --- | --- | --- |
| SSH 会话内 | 标题栏工具条的「文件传输」按钮（完全全屏时在悬浮药丸里） | SFTP | 终端右侧停靠侧栏，可拖动分隔条调宽，宽度在各会话间共用；按钮在侧栏展开时为品牌色 |
| 不连接会话（SSH） | 「我的连接」行右键 / 首页行右键 / 详情面板「⋯」→「文件传输…」 | SFTP | 在主窗口 Tab 条里开一个 Tab，与 SSH / RDP 会话同处一条 Tab 条 |
| 不连接会话（RDP） | 同上 | SMB 管理共享（默认）或 SFTP | 通道在「编辑连接 → 文件传输」中设置 |
| VNC | 入口置灰 | — | VNC 协议本身不支持文件传输，悬停提示原因 |

要点：

- **文件传输 Tab 不是会话**：不计入「已连接 N 个会话」，不参与全屏与会话工具条。
- **同一连接只开一个 Tab**：再次点「文件传输…」会聚焦已有 Tab，不会对同一台主机重复建立传输连接。
- 关闭 Tab：点标签头的 ×，或按 `Ctrl+W`；退出应用也会一并释放传输连接。
- 会话内侧栏与独立 Tab 是**同一个面板控件**，能力完全一致。
- 会话内侧栏只在 SSH 会话里出现；RDP 会话内仍沿用 mstsc 自带的剪贴板复制文件 / 驱动器重定向，本版没有改动。

## 2. 面板能力

- **浏览**：路径栏（面包屑，可点击；`Ctrl+L` 切换为可编辑路径框，回车跳转）、上一级、刷新（`F5`）。目录在前、名称排序；列表显示大小与修改时间；文件与文件夹使用 **Windows 资源管理器同款系统图标**（按扩展名取，并缓存）。
- **上传**：上传文件（可多选）/ 上传文件夹；右键空白处「上传文件到此处…」。
- **下载**：选中一项或多项（`Ctrl` / `Shift` 多选）→「下载…」，选择本地目标文件夹；文件夹会递归下载。
- **管理**：新建文件夹、重命名（`F2`）、删除（`Del`，递归删除会二次确认并按危险样式提示）、复制路径。
- **传输队列**：面板底部显示每一项的进度（已传 / 总量、第几个文件、当前文件），可单项取消、全部取消、清除已完成；单项失败不影响其余项目。
- **覆盖确认**：目标已存在时弹出对话框，可选 **跳过 / 保留两者（自动改名）/ 覆盖 / 取消传输**（文件与文件夹同名、类型不同时无法覆盖，只能跳过或改名），并可勾选「对本批后续的同名项目执行相同操作」。
- **不含**：拖拽上传下载、断点续传、文件内容预览与编辑。

## 3. 通道说明

### 3.1 SFTP

- 使用 SSH.NET。**会话内**：复用该会话已建立的认证信息另开一条**独立的 SFTP 连接**——不占用终端通道，也不再次读取凭据库，因此传大文件时终端仍可输入。**不连接会话时**：按连接保存的凭据建立连接，打开后立即释放凭据。
- 主机密钥沿用现有策略：首次连接记录指纹（TOFU）并弹窗确认，指纹变化强警告，绝不静默接受。
- 服务器需启用 SFTP 子系统；不支持 keyboard-interactive / 多因素认证（与现有 SSH 连接一致）。
- 常见错误（子系统未启用、权限不足、路径不存在、磁盘已满、连接中断）会转成中文提示。

### 3.2 SMB 管理共享（RDP 主机默认）

- 通过 Windows 系统 WNet API 用**本连接保存的 Windows 账号**认证（`CONNECT_TEMPORARY`，不持久化、不弹系统登录框），再访问 `\主机\C$` 之类的 UNC 路径。根目录列出该主机的管理共享。
- 账号格式：域账号按 `域\用户`，本地账号按 `主机\用户`。
- **前提与限制**（编辑器里也有说明）：
  - 只用 **445 端口**；连接前先做 TCP 预探测，不可达约 4 秒内给出明确提示，连接本身有 20 秒超时。
  - 目标需允许管理共享（未被策略禁用），账号需有相应权限。
  - 通常仅适用于**局域网 / VPN**，不要把 445 暴露到公网。
  - **错误 1219**：本机 Windows 会话里已经用另一个账号连过该主机时，系统不允许再用第二个账号。RemoteFlow **不会替你强行断开**已有连接，只提示你先自行断开（例如在命令行 `net use` 查看与断开）。
  - 仅 Windows 版提供。

### 3.3 RDP 主机改走 SFTP

在「编辑连接 → 文件传输」把通道选为 SFTP 并填写端口（默认 22）。目标 Windows 需要安装并运行 OpenSSH Server。Windows OpenSSH 的用户名格式（`域\用户` / `用户@域`）**尚未在真机验证**，见第 6 节。

通道与端口按连接保存在连接的 `options_json` 里：纯加法、无数据库迁移，老数据自动取默认值（SSH → SFTP，RDP → SMB）。

## 4. 安全设计

| 风险 | 处理 |
| --- | --- |
| 下载 / 拷贝时被恶意文件名逃出目标目录 | 远端文件名先净化（拒绝 `..`、路径分隔符、盘符、`:`、Windows 保留名与非法字符，超长截断），落盘前再校验完整路径仍在目标目录之下；SMB 侧同样拒绝逃出所选共享 |
| 传输中断留下半截文件 | 下载先写 `基名.8位随机.rfpart` 临时文件，成功后原子改名；上传先写远端临时名再改名；取消 / 失败会清理临时文件，最终路径不会出现半截文件 |
| 覆盖时丢数据 | 覆盖使用原子替换，失败保留原文件，不做「先删后写」 |
| 符号链接 / junction 造成环或越界 | 递归时**不跟随**符号链接与 reparse point，计入该项的「已跳过」并给出说明 |
| 目录过深 / 条目过多拖垮客户端 | 递归深度上限 64、单次展开条目上限 20 万；同时最多并行 2 个传输 |
| 删除误操作 | 删除需确认，递归删除按危险样式；SMB 的共享列表（根）是只读视图，不允许在其上上传、删除或重命名，必须先进入某个共享 |
| 凭据泄露 | 凭据只在建立通道时解析、用完即释放；日志只记录连接 Id、通道、操作类型、字节数与异常类型，**不记录文件内容**，路径仅在 Debug 级别出现；界面与异常信息不含账号密码 |
| 关闭 / 退出时的残留 | 关闭 Tab、断开会话、退出应用都会取消在途传输并释放 SFTP / SMB 连接；有进行中的传输时先确认 |

## 6. 已知限制与未验证项

**本版已知限制**

- 仅 Windows 版；**macOS 版没有文件传输**（本机无法编译与验证 macOS 界面），共享层改动均为加法。
- SMB：仅 445 端口，需管理共享可用，通常仅限局域网 / VPN。
- SFTP：需目标启用 SFTP 子系统，不支持 keyboard-interactive / 多因素认证。
- 不含拖拽、断点续传、文件预览与编辑；符号链接不跟随。
- 云同步：新字段对旧版本客户端是被忽略的；旧版本客户端把连接同步回来可能把「文件传输通道」重置为默认值。macOS 编辑器保存连接时是否保留该字段尚未验证。

**发布时未在真实主机上验证（仅有自动化测试覆盖，含假文件系统）**

- SSH 会话内 SFTP 的完整往返（上传后再下载比对 SHA-256）、取消、覆盖确认、大文件（约 200 MB）传输期间终端响应、传输中断开会话。
- SMB 通道：共享列表、`C$` 下读写、错误 1219、445 不可达。
- Windows OpenSSH 的用户名格式，以及「RDP 主机走 SFTP」。
- 发布前的实机走查只确认了：产物能启动、版本号正确、设置页可进入、正常退出；以及开发期在真实 SSH 主机上，会话内侧栏能展开并列出远端目录。

建议首次使用时先在测试目录里试传，确认与你的服务器环境相容后再用于重要数据。

## 7. 实现结构（面向开发者）

依赖方向不变：`UI → Presentation → Application → Core ← Infrastructure.* / Protocol.*`。

| 层 | 内容 |
| --- | --- |
| `RemoteFlow.Core/FileTransfer` | `IRemoteFileSystem`（与通道无关的最小原语：列目录 / 上传 / 下载 / 新建 / 重命名 / 删除）、`RemoteFileEntry`、`RemotePath`、`LocalNameSanitizer`、`IRemoteFileSystemFactory`、`IFileTransferSession`；`ConnectionProfile.FileTransfer`（`FileTransferOptions`：通道 Auto / Sftp / Smb 与 SFTP 端口） |
| `RemoteFlow.Application/FileTransfer` | `FileTransferService`（传输队列、临时文件 + 原子改名、冲突处理、递归上限、并发控制、取消）；`FileTransferConnector`（按协议与通道选工厂并解析凭据，打开后立即释放） |
| `RemoteFlow.Protocol.Ssh` | `SftpFileSystem`、`SftpFileSystemFactory`；从 `SshSession` 抽出 `SshConnectionInfoFactory` 与 `SshHostKeyGate`，`SshSession` 实现 `IFileTransferSession` |
| `RemoteFlow.Infrastructure.Windows/Smb` | `SmbFileSystem`（UNC 映射、分块拷贝、穿越与 reparse point 防护）、`WNetSmbAuthenticator`（可注入假实现便于测试）、`SmbFileSystemFactory` |
| `RemoteFlow.Presentation` | `FileTransferViewModel`（面板逻辑）、`FileTransferTabViewModel`（工作区 Tab）、`IFileTransferLauncher`（入口只表达意图，由主窗口开 Tab）、`SessionTabViewModel`（会话内侧栏开关）、`ConnectionEditorViewModel`（通道 / 端口） |
| `RemoteFlow.App` | `FileTransferPanel`（侧栏与 Tab 共用）、`SessionHostView` 的分列 + `GridSplitter`（终端是 WebView2，不能被 WPF 元素叠盖，所以侧栏靠分列并排）、`ShellIconProvider`（系统文件图标）、覆盖确认与文本输入对话框 |

设计取舍：安全与编排（临时文件、净化、限制、冲突）放在 `FileTransferService`，而不是各通道里，这样 SFTP 与 SMB 的行为一致、只需测一处；共享层（Core / Presentation）仅做加法，保证 macOS 工程不受影响。
