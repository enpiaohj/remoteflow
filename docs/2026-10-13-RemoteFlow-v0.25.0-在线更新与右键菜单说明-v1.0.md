# RemoteFlow v0.25.0 在线更新与右键菜单说明

> 文档版本 v1.0（2026-10-13）｜适用版本：RemoteFlow Windows v0.25.0｜macOS 版本未含本文所述功能

v0.25.0 做了两件事：**应用内在线更新**，以及**全部右键菜单（含托盘菜单）的统一**。
同时把 v0.24.1 的两项改动（玻璃外观下老服务器 RDP 画面发白的修复、RDP 颜色深度选项）一并收录在第 4 节，便于查阅。

---

## 1. 应用内在线更新

### 1.1 在哪里

「关于」页新增 **软件更新** 区；有新版本时底部状态栏左侧出现「有新版本可用」，点击跳到这里。托盘菜单里也有「检查更新」。

| 按钮 | 作用 |
| --- | --- |
| 检查更新 | 访问 GitHub 发布页查询最新版本 |
| 下载并更新 | 下载新版本并校验；完成后显示「立即重启」 |
| 立即重启 | 确认后退出并启动新版本（会断开当前会话与进行中的文件传输） |
| 打开下载页 | 用浏览器打开该版本的发布页，手动下载 |

### 1.2 默认不联网

- **「启动时自动检查更新」默认关闭。** 只有你点「检查更新」，或显式打开这个开关，应用才会访问 GitHub。
- 打开开关后，每次启动约 8 秒后检查一次：**只提示，不自动下载**；检查失败（没网、访问不了 GitHub）不打扰。
- 「关于 → 隐私与数据 → 对外通信」的说明已同步更新。

### 1.3 更新过程

1. **查询**：读取公开仓库的 GitHub Releases（无需登录）。仓库里 Windows 与 macOS 两条版本线的发布混在一起，应用只取形如 `v0.25.0` 的 Windows 版本，且必须带有 `RemoteFlow-v<版本>-win-x64.exe` 这个产物；草稿与预发布版本不算。
2. **下载**：下载到系统临时目录的 `RemoteFlow-update` 文件夹。
3. **校验**：文件大小与 SHA-256 必须与发布页登记的逐位一致，否则丢弃并提示。发布页没有提供 SHA-256、或下载地址不是 GitHub 的 HTTPS 地址时，拒绝自动更新。
4. **替换**：**在程序退出的最后一步**把旧文件改名为 `<原文件名>.old`，把新文件写到原路径。点「立即重启」会在替换后自动启动新版本；不点、之后正常退出也会完成替换，下次启动就是新版本。
5. **清理**：新版本启动时删除 `.old` 文件。

> 为什么不是下载完立刻替换：程序是单文件可执行文件，运行期间会按需从自身读取尚未加载的组件。实测运行中换掉文件后，这些读取全部失败。所以替换只在退出时进行，下载完成到退出之前程序完全正常。

### 1.4 开机启动、快捷方式会不会失效

不会。**更新不改变程序路径和文件名**，所以开机启动项（注册表 Run 值）、桌面快捷方式、任务栏固定都继续有效。更新后首次启动还会按当前设置重写一次开机启动项作为兜底。

代价是：如果文件名里带版本号（例如 `RemoteFlow-v0.24.1-win-x64.exe`），更新后文件名不变，**以程序里显示的版本号为准**（标题栏、关于页、托盘提示）。

### 1.5 失败时会怎样

| 情况 | 表现 |
| --- | --- |
| 检查失败（没网 / 访问不了 GitHub） | 手动检查时提示检查网络或代理；自动检查时静默 |
| 下载中断 | 提示可重试，或打开下载页手动更新 |
| 校验不通过 | 丢弃已下载的文件并提示 |
| 程序所在目录没有写入权限（如 `Program Files`） | 下载后立即提示，改为手动更新 |
| 退出时替换失败（文件被占用等） | 自动回滚到原文件；若是「立即重启」，会重新启动原版本并提示「更新未完成」 |

任何失败都保留「打开下载页」这条退路。

### 1.6 限制与安全说明

- **仅单文件发布形态支持应用内更新**（发布页下载的 exe）。从源码运行的开发态只提供「打开下载页」。
- **产物没有代码签名。** SHA-256 校验保证「下载到的就是 GitHub 发布页上的那个文件」，不能防止发布账号被盗后发布恶意版本。
- 国内访问 GitHub 可能较慢或失败；应用使用系统代理设置。
- v0.24.1 及更早版本没有这个功能，需要先手动安装 v0.25.0，之后的版本才能在应用内更新。
- macOS 版没有应用内更新。

## 2. 右键菜单统一

### 2.1 统一的约定

全应用的右键菜单（包括托盘菜单）现在遵循同一套约定：

- **分组顺序固定**：会话动作 → 工具 → 整理 → 跳转 → 破坏性操作。
- **破坏性操作用警示色，并且永远在菜单最后一组**：删除连接、删除凭据、删除分组、删除文件、删除所选、关闭全部会话、断开全部会话。
- **每个动作有图标**，带图标与不带图标的菜单项文字始终对齐；子菜单里的分组名、标签名是数据而非动作，不加图标。
- **同一动作叫法一致**：

| 现在的叫法 | 以前的叫法 |
| --- | --- |
| 编辑连接 | 编辑 / 编辑连接 |
| 测试连接 | 测试连接 / 测试连接（Ping） |
| 创建副本 | 复制连接 |
| 复制地址 | 复制 IP |
| 在工作台中显示 | 管理连接 |
| 收藏 / 取消收藏（图标同步变为空心 / 实心星） | 打勾项与文字切换两种形式并存 |

- 去掉了详情面板里永远禁用的两个占位项。

### 2.2 各菜单内容

**连接行（我的连接 / 收藏 / 最近连接）**

| 组 | 菜单项 | 说明 |
| --- | --- | --- |
| 会话 | 连接 / 切换到会话（`Enter`） | 已有会话时为「切换到会话」 |
| | 新建会话、重新连接、断开连接 | 仅在该连接已有活动会话时出现 |
| 工具 | 测试连接、文件传输…、复制地址 | VNC 的「文件传输…」置灰并说明原因 |
| 整理 | 编辑连接（`F2`）、创建副本、收藏 / 取消收藏、移动到分组 ▸ | 创建副本与移动到分组仅在「我的连接」 |
| 跳转 | 在工作台中显示 | 仅在收藏 / 最近连接视图 |
| 破坏性 | 删除连接（`Del`） | 仅在「我的连接」，需确认 |

**首页行（最近连接 / 收藏）**：连接 / 切换到会话、新建会话、重新连接、断开连接｜测试连接、文件传输…、复制地址｜编辑连接、收藏 / 取消收藏｜在工作台中显示。首页不提供删除。

**连接详情面板**：「连接 ▾」＝ 新建会话、重新连接、断开连接（有会话时）｜测试连接、文件传输…｜编辑连接；「⋯」＝ 复制地址、收藏 / 取消收藏、创建副本。

**会话标签**：重新连接、文件传输 / 收起文件传输（仅 SSH）、复制地址、全屏（`F11`）｜关闭会话（`Ctrl+W`）、关闭其他会话、关闭右侧会话｜关闭全部会话。

**文件传输标签**（新增）：复制地址｜关闭文件传输（`Ctrl+W`）。

**凭据行**：编辑凭据（`F2`）、复制用户名｜删除凭据（`Del`）。只提供复制用户名（含域），**不提供密码或私钥的复制入口**。

**分组**：新建连接、新建子分组｜编辑分组｜删除分组。内置分组不显示编辑与删除。

**文件列表**：下载…、重命名（`F2`）、复制路径｜上传文件到此处…、新建文件夹…、刷新（`F5`）｜删除（`Del`）。

**批量操作**：全选当前列表、清空选择｜批量连接、收藏、移动到分组 ▸、添加标签 ▸｜删除所选。

### 2.3 托盘菜单

托盘菜单从系统默认样式换成了应用自己的菜单样式：跟随深浅色主题，带图标，与应用内菜单外观一致。

| 组 | 菜单项 |
| --- | --- |
| 窗口 | 打开 RemoteFlow / 隐藏 RemoteFlow |
| 连接与会话 | 新建连接 ▸（RDP / SSH / VNC）、最近连接 ▸（最多 5 条 + 查看全部）、活动会话（N）▸（逐个切换 + 断开全部会话） |
| 设置 | 设置、开机启动（勾选表示已开启）、检查更新 |
| 退出 | 退出 RemoteFlow |

- 「检查更新」会打开「关于」页并检查一次；已发现新版本时显示为「有新版本可用…」，已下载待重启时显示为「重启以完成更新」。
- **托盘图标的悬停提示现在带版本号**：`RemoteFlow v0.25.0`，有会话时为 `RemoteFlow v0.25.0 — N 个会话已连接`。
- 单击显示 / 隐藏主窗口、双击打开并置前的行为不变。

### 2.4 新增的快捷键

菜单里标注的快捷键都是真实绑定的：

| 位置 | 快捷键 | 动作 |
| --- | --- | --- |
| 连接列表 | `Enter` | 连接 / 切换到会话（原有） |
| 连接列表 | `F2` | 编辑连接（新增） |
| 连接列表 | `Del` | 删除连接，仅「我的连接」，需确认（新增） |
| 凭据列表 | `F2` / `Del` | 编辑 / 删除凭据，删除需确认（新增） |
| 会话 | `F11` | 全屏逐档切换（原有，菜单新增入口） |
| 会话 / 文件传输标签 | `Ctrl+W` | 关闭当前标签（原有） |
| 文件列表 | `F2` / `Del` / `F5` / `Ctrl+L` | 重命名 / 删除 / 刷新 / 编辑路径（原有） |

多选模式下 `F2`、`Del` 不生效，避免误操作。

## 3. 验证情况

**已实测**

- 在线更新：用一个版本号伪装成 0.24.0 的测试构建，对线上真实的 v0.24.1 发布完成了整个流程——默认不联网、检查到新版本、下载约 20 秒、SHA-256 与发布记录一致、退出时替换、从同一路径启动新版本、旧文件清理；「立即重启」与「不重启直接退出」两条路径都跑通。
- 连接行与凭据行的右键菜单：截图确认图标、对齐、警示色、收藏状态显示正常（浅色主题）。

**未实测（发布时如实标注）**

- **托盘菜单的实际显示**（弹出位置、点击外部关闭、子菜单、深色主题）在开发阶段没有截到图，由用户验收。
- 开机启动项在真实开启状态下的更新后表现：按「路径不变」的设计推断有效，没有在开启开机启动的环境里实测。
- 更新的失败分支（目录无写权限、下载中断、校验失败、退出时替换失败后的回滚与提示）只有自动化测试覆盖。
- 新绑定的 `F2` / `Del`、会话标签与文件传输标签菜单、分组与文件列表菜单、深色与玻璃外观下的菜单，只有编译与标记测试覆盖。
- macOS 未构建、未验证。

**自动化测试**：Core.Tests 151、IntegrationTests 448（含更新相关 22 项）、IntegrationTests.Windows 142（含菜单约定 16 项），均通过。

## 4. 附：v0.24.1 的两项改动

- **修复：玻璃外观（亚克力 / 云母）下连接 Windows Server 2003 等较老系统时远程画面几乎全白。** 主窗口把系统材质扩展到整个客户区后，老服务器使用的 GDI 位图绘制不带透明度信息，被系统当成透明。现在玻璃外观下把 RDP 画面区域标记为不透明；纯色外观不受影响。
- **新增：RDP 颜色深度选项。** 编辑连接 → RDP → 体验 → 颜色深度，可选 32 / 24 / 16 / 15 位，默认 32 位。远端不支持时会自动协商为它支持的最高值。该选项目前只对 Windows 版生效。

## 5. 实现结构（面向开发者）

| 位置 | 内容 |
| --- | --- |
| `RemoteFlow.Infrastructure/Updates` | `GitHubReleaseParser`（发布列表筛选，纯函数）、`GitHubUpdateService`（查询、下载、校验）、`UpdateRelease` / `IUpdateService` |
| `RemoteFlow.Presentation` | `UpdateViewModel`（状态机：未检查 / 检查中 / 已是最新 / 有新版本 / 下载中 / 待重启 / 失败）、`IUpdateInstaller`（平台落地接口）；`AppSettings.AutoCheckUpdates` |
| `RemoteFlow.App/Services/WpfUpdateInstaller.cs` | 可写性检查、登记更新包、退出时替换与回滚、重启；`App.OnExit` 最后一步调用 `CompletePendingUpdateOnExit` |
| `RemoteFlow.App/Views/MenuItemAssist.cs` | 菜单项的图标键与警示色附加属性；菜单项模板在 `Themes/Controls.Collections.xaml` |
| `RemoteFlow.App/Services/TrayService.cs` | 托盘菜单改为 WPF `ContextMenu`，于光标处弹出并把弹出窗口设为前台以支持点击外部关闭 |

共享层（`Core` / `Presentation`）的改动均为加法：没有更新实现的平台不注册 `UpdateViewModel`，关于页不显示更新区。
