# RemoteFlow 标题栏自适应会话选择器实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 会话达到 5 个或标题栏可用宽度不足时，把独立会话 Tab 自适应合并为“当前会话”下拉选择器，同时保持连接工作台、会话工具条和窗口按钮稳定可用。

**Architecture:** `MainWindow` 继续持有完整 `Tabs` 与常驻会话视图，只在标题栏切换普通 Tab 头和紧凑选择器两种呈现；纯函数 `SessionTabLayoutPolicy` 根据会话数量和实测宽度决定模式。新的 `SessionTabSelector` 仅负责会话选择菜单、键盘导航和单项关闭，复用现有 `SessionTabViewModel` 与共享右键菜单，不创建或销毁协议会话。

**Tech Stack:** .NET 10、WPF、CommunityToolkit.Mvvm、xUnit、WindowChrome、Popup/ListBox。

- [ ] **Step 3：实现最小纯规则**

```csharp
internal static class SessionTabLayoutPolicy
{
    internal const int CompactSessionThreshold = 5;
    private const double WidthTolerance = 1;

    internal static bool ShouldUseCompactMode(
        int sessionCount, double requiredWidth, double availableWidth)
        => sessionCount >= CompactSessionThreshold
           || requiredWidth > availableWidth + WidthTolerance;
}
```

- [ ] **Step 3：实现模式计算**

```csharp
private void EvaluateSessionTabLayout()
{
    var sessionCount = _viewModel.Tabs.OfType<SessionTabViewModel>().Count();
    var compact = SessionTabLayoutPolicy.ShouldUseCompactMode(
        sessionCount,
        TabScrollViewer.ExtentWidth,
        Math.Max(0, TabStripHost.ActualWidth - TabStripHost.Padding.Left - TabStripHost.Padding.Right));

    if (_isCompactTabMode == compact) return;
    _isCompactTabMode = compact;
    NormalTabStrip.Visibility = compact ? Visibility.Hidden : Visibility.Visible;
    CompactTabStrip.Visibility = compact ? Visibility.Visible : Visibility.Collapsed;

    if (!compact)
        Dispatcher.BeginInvoke(EnsureSelectedTabVisible, DispatcherPriority.Loaded);
}
```
