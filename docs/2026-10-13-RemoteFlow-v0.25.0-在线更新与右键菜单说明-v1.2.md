## 1. 应用内在线更新

### 1.1 在哪里

「关于」页新增 **软件更新** 区；有新版本时底部状态栏左侧出现「有新版本可用」，点击跳到这里。托盘菜单里也有「检查更新」。

| 按钮 | 作用 |
| --- | --- |
| 检查更新 | 访问 GitHub 发布页查询最新版本 |
| 下载并更新 | 下载新版本并校验；完成后显示「立即重启」 |
| 取消下载 | 下载中出现；取消后可随时重新下载（v0.25.2） |
| 立即重启 | 确认后退出并启动新版本（会断开当前会话与进行中的文件传输） |
| 打开下载页 | 用浏览器打开该版本的发布页，手动下载 |

### 1.2 默认不联网

- **「启动时自动检查更新」默认关闭。** 只有你点「检查更新」，或显式打开这个开关，应用才会访问 GitHub。
- 打开开关后，每次启动约 8 秒后检查一次：**只提示，不自动下载**；检查失败（没网、访问不了 GitHub）不打扰。
- 「关于 → 隐私与数据 → 对外通信」的说明已同步更新。

### 1.3 更新过程

1. **查询**：读取公开仓库的 GitHub Releases（无需登录）。仓库里 Windows 与 macOS 两条版本线的发布混在一起，应用只取形如 `v0.25.0` 的 Windows 版本，且必须带有 `RemoteFlow-v<版本>-win-x64.exe` 这个产物；草稿与预发布版本不算。
2. **下载**：下载到系统临时目录的 `RemoteFlow-update` 文件夹。连续 45 秒收不到数据会判定为连接停滞并报错；下载中可以取消。
3. **校验**：文件大小与 SHA-256 必须与发布页登记的逐位一致，否则丢弃并提示。发布页没有提供 SHA-256、或下载地址不是 GitHub 的 HTTPS 地址时，拒绝自动更新。
4. **落地**：**在程序退出的最后一步**进行（见下方说明）。点「立即重启」会在落地后自动启动新版本；不点、之后正常退出也会落地，下次启动就是新版本。
5. **善后**：新版本启动时删除旧文件与遗留的临时文件。

> 为什么不是下载完立刻落地：程序是单文件可执行文件，运行期间会按需从自身读取尚未加载的组件。实测运行中动了这个文件后，这些读取全部失败。所以落地只在退出时进行，下载完成到退出之前程序完全正常。

### 1.4 文件名、开机启动与快捷方式（v0.25.2 起）

**文件名跟随版本。** 判断依据是当前文件名：

| 当前文件名 | 更新后 |
| --- | --- |
| 发布产物的命名形式，如 `RemoteFlow-v0.25.2-win-x64.exe` | 新版本以自己的产物名写到同一目录，如 `RemoteFlow-v0.25.3-win-x64.exe`；旧文件由新版本启动后删除 |
| 自己改过的名字，如 `RemoteFlow.exe` | 名字不变，原地替换（旧文件暂存为 `<名字>.old`，新版本启动后删除） |

文件名变化时，程序会一并处理指向旧文件的入口：

- **开机启动项**（注册表 Run 值）改指向新文件，并保留「随系统启动时驻留托盘」的参数。
- **快捷方式**：桌面、开始菜单、启动文件夹、任务栏固定 / 快速启动栏里目标为旧文件的 `.lnk` 改指向新文件。只改目标完全等于旧路径的快捷方式，不动其它文件。
- 这两步在**退出时做一次，新版本启动时再补一次**，之后才删除旧文件。

落地的具体做法：新文件先完整写成 `<新名字>.new`，核对大小后再改名到位，所以任何时刻目录里都不会出现名字正确但内容不完整的 exe。新文件旁会留一个 `<新名字>.replaces` 小文件记下被取代的旧文件名，供新版本启动时善后，完成后自动删除。

> **v0.25.0 – v0.25.1 的行为不同**：这两个版本更新时保持原文件名与路径不变。因此从它们更新到 v0.25.2 时文件名仍不会变；改名要到「从 v0.25.2 更新到之后的版本」时才生效。想让文件名现在就对上，可以手动把文件改名为 `RemoteFlow-v0.25.2-win-x64.exe`，再到「设置 → 启动与托盘」把「开机时启动 RemoteFlow」关掉重开一次。

### 1.5 失败时会怎样

| 情况 | 表现 |
| --- | --- |
| 检查失败 | 手动检查时按原因提示：GitHub 限制了请求频率、连接超时、GitHub 返回错误、无法访问；自动检查时静默 |
| 下载中断 / 停滞 | 提示原因（网络中断、长时间没有数据、临时目录磁盘空间不足或没有权限），可重试或打开下载页 |
| 取消下载 | 回到「发现新版本」状态，可随时重新下载 |
| 校验不通过 | 丢弃已下载的文件并提示 |
| 程序所在目录没有写入权限（如 `Program Files`） | 下载后立即提示，改为手动更新 |
| 退出时落地失败（磁盘空间不足、文件被占用、更新包被清理等） | 原文件保持可用，不留半截文件；若是「立即重启」，重新启动原版本；**下次手动打开时提示一次「更新未完成」**（随系统启动驻留托盘时不弹窗，留到手动打开时提示） |
| 落地过程中被强制结束（如关机） | 只可能留下一个 `.new` 临时文件，下次启动时清理；现有安装不受影响 |
| 启动项 / 快捷方式改指向失败 | 不影响更新；新版本启动时会再试一次。仍改不了的快捷方式需要手动重建 |
| 点了「立即重启」但退出被别的确认拦下 | 撤销待重启；更新包保留，下次退出时照常落地 |
| 旧文件暂时删不掉（仍被占用） | 保留善后记录，之后每次启动再试 |

任何失败都保留「打开下载页」这条退路。

### 1.6 限制与安全说明

- **仅单文件发布形态支持应用内更新**（发布页下载的 exe）。从源码运行的开发态只提供「打开下载页」。
- **产物没有代码签名。** SHA-256 校验保证「下载到的就是 GitHub 发布页上的那个文件」，不能防止发布账号被盗后发布恶意版本。
- 更新包校验通过后到退出落地之间，如果被本机其它程序篡改，不会被发现（能做到这一点的程序本来也能直接改程序文件）。
- 新版本自身无法启动（例如被安全软件拦截）时，旧文件仍保留、可手动运行，但启动项与快捷方式已经指向新文件。
- 更新中途程序崩溃或被结束进程时不会落地，下次启动需要重新检查并下载，现有安装不受影响。
- 国内访问 GitHub 可能较慢或失败；应用使用系统代理设置。
- v0.24.1 及更早版本没有这个功能，需要先手动安装带更新功能的版本。
- macOS 版没有应用内更新。

## 2. 右键菜单统一

### 2.1 统一的约定

全应用的右键菜单（包括托盘菜单）现在遵循同一套约定：

- **分组顺序固定**：会话动作 → 工具 → 整理 → 跳转 → 破坏性操作。
- **破坏性操作用警示色，并且永远在菜单最后一组**：删除连接、删除凭据、删除分组、删除文件、删除所选、关闭全部会话、断开全部会话。
- **每个动作有图标**，带图标与不带图标的菜单项文字始终对齐；子菜单里的分组名、标签名是数据而非动作，不加图标。
- **同一动作叫法一致**：

| 现在的叫法 | 以前的叫法 |
| --- | --- |
| 编辑连接 | 编辑 / 编辑连接 |
| 测试连接 | 测试连接 / 测试连接（Ping） |
| 创建副本 | 复制连接 |
| 复制地址 | 复制 IP |
| 在工作台中显示 | 管理连接 |
| 收藏 / 取消收藏（图标同步变为空心 / 实心星） | 打勾项与文字切换两种形式并存 |

- 去掉了详情面板里永远禁用的两个占位项。

### 2.2 各菜单内容

**连接行（我的连接 / 收藏 / 最近连接）**

| 组 | 菜单项 | 说明 |
| --- | --- | --- |
| 会话 | 连接 / 切换到会话（`Enter`） | 已有会话时为「切换到会话」 |
| | 新建会话、重新连接、断开连接 | 仅在该连接已有活动会话时出现 |
| 工具 | 测试连接、文件传输…、复制地址 | VNC 的「文件传输…」置灰并说明原因 |
| 整理 | 编辑连接（`F2`）、创建副本、收藏 / 取消收藏、移动到分组 ▸ | 创建副本与移动到分组仅在「我的连接」 |
| 跳转 | 在工作台中显示 | 仅在收藏 / 最近连接视图 |
| 破坏性 | 删除连接（`Del`） | 仅在「我的连接」，需确认 |

**首页行（最近连接 / 收藏）**：连接 / 切换到会话、新建会话、重新连接、断开连接｜测试连接、文件传输…、复制地址｜编辑连接、收藏 / 取消收藏｜在工作台中显示。首页不提供删除。

**连接详情面板**：「连接 ▾」＝ 新建会话、重新连接、断开连接（有会话时）｜测试连接、文件传输…｜编辑连接；「⋯」＝ 复制地址、收藏 / 取消收藏、创建副本。

**会话标签**：重新连接、文件传输 / 收起文件传输（仅 SSH）、复制地址、全屏（`F11`）｜关闭会话（`Ctrl+W`）、关闭其他会话、关闭右侧会话｜关闭全部会话。

**文件传输标签**（新增）：复制地址｜关闭文件传输（`Ctrl+W`）。

**凭据行**：编辑凭据（`F2`）、复制用户名｜删除凭据（`Del`）。只提供复制用户名（含域），**不提供密码或私钥的复制入口**。

**分组**：新建连接、新建子分组｜编辑分组｜删除分组。内置分组不显示编辑与删除。

**文件列表**：下载…、重命名（`F2`）、复制路径｜上传文件到此处…、新建文件夹…、刷新（`F5`）｜删除（`Del`）。

**批量操作**：全选当前列表、清空选择｜批量连接、收藏、移动到分组 ▸、添加标签 ▸｜删除所选。

### 2.3 托盘菜单

托盘菜单从系统默认样式换成了应用自己的菜单样式：跟随深浅色主题，带图标，与应用内菜单外观一致。

| 组 | 菜单项 |
| --- | --- |
| 窗口 | 打开 RemoteFlow / 隐藏 RemoteFlow |
| 连接与会话 | 新建连接 ▸（RDP / SSH / VNC）、最近连接 ▸（最多 5 条 + 查看全部）、活动会话（N）▸（逐个切换 + 断开全部会话） |
| 设置 | 设置、开机启动（勾选表示已开启）、检查更新 |
| 退出 | 退出 RemoteFlow |

- 「检查更新」会打开「关于」页并检查一次；已发现新版本时显示为「有新版本可用…」，已下载待重启时显示为「重启以完成更新」。
- **托盘图标的悬停提示现在带版本号**：`RemoteFlow v0.25.0`，有会话时为 `RemoteFlow v0.25.0 — N 个会话已连接`。
- 单击显示 / 隐藏主窗口、双击打开并置前的行为不变。

### 2.4 新增的快捷键

菜单里标注的快捷键都是真实绑定的：

| 位置 | 快捷键 | 动作 |
| --- | --- | --- |
| 连接列表 | `Enter` | 连接 / 切换到会话（原有） |
| 连接列表 | `F2` | 编辑连接（新增） |
| 连接列表 | `Del` | 删除连接，仅「我的连接」，需确认（新增） |
| 凭据列表 | `F2` / `Del` | 编辑 / 删除凭据，删除需确认（新增） |
| 会话 | `F11` | 全屏逐档切换（原有，菜单新增入口） |
| 会话 / 文件传输标签 | `Ctrl+W` | 关闭当前标签（原有） |
| 文件列表 | `F2` / `Del` / `F5` / `Ctrl+L` | 重命名 / 删除 / 刷新 / 编辑路径（原有） |

多选模式下 `F2`、`Del` 不生效，避免误操作。

## 4. 附：v0.24.1 的两项改动

- **修复：玻璃外观（亚克力 / 云母）下连接 Windows Server 2003 等较老系统时远程画面几乎全白。** 主窗口把系统材质扩展到整个客户区后，老服务器使用的 GDI 位图绘制不带透明度信息，被系统当成透明。现在玻璃外观下把 RDP 画面区域标记为不透明；纯色外观不受影响。

## 6. 随系统启动时驻留托盘（v0.25.1）

### 6.1 行为

| 启动方式 | 表现 |
| --- | --- |
| 随系统启动（设置里开了「开机时启动 RemoteFlow」） | 只出现托盘图标，不弹主窗口 |
| 手动打开（双击程序、开始菜单、快捷方式） | 正常显示主窗口 |
| 程序已在托盘里运行时再次手动打开 | 已在运行的那个实例显示主窗口，不会启动第二个 |
| 应用内更新后的重启 | 正常显示主窗口 |

从托盘唤出窗口的方式不变：单击托盘图标显示 / 隐藏，双击打开并置前，或用托盘菜单的「打开 RemoteFlow」。

### 6.2 原理

- 开机启动项（注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下的 `RemoteFlow`）写入的命令现在是
  `"<程序路径>" --startup`。程序带 `--startup` 启动时只初始化托盘，不显示主窗口。
- **旧启动项自动升级**：v0.25.0 及更早版本写入的启动项没有这个参数。新版本每次启动时检查一次，
  发现启动项指向当前程序文件且缺少参数就补上。从其它目录运行的副本（例如试用包）不会改动已有启动项。
- **再次启动时唤出窗口**：窗口隐藏在托盘时，进程没有可激活的窗口句柄，旧的做法（找到窗口并激活）无效。
  现在已在运行的实例监听一个本机命名事件，再次启动的实例置位该事件后退出，由前者显示主窗口。
  随系统启动的重复实例（带 `--startup`）不会触发唤出。

### 6.3 注意

- **升级后的第一次开机仍会显示窗口**：旧启动项要等新版本运行过一次才会带上参数。
  想立即生效，可在「设置 → 启动与托盘」把「开机时启动 RemoteFlow」关掉再打开一次。
- 没有「开机启动时显示窗口」的开关，随系统启动固定为驻留托盘。
- 应用内更新若改了文件名（v0.25.2 起，见 1.4），启动项会自动改指向新文件并保留启动参数。

### 6.4 验证情况

- 已实测：带 `--startup` 启动后进程存活且没有可见窗口；随后手动再启动一次，已在运行的实例显示出主窗口，
  第二个进程以退出码 0 结束；整个过程没有改动注册表里已有的启动项。
- 未实测：真实重启电脑后的表现；旧启动项在真实注册表中的升级（只有判断逻辑的自动化测试）。
